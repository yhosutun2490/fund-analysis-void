# request-response-validation

在 Void + Drizzle + Zod 的架構中，你可以直接從 Drizzle 的資料表產生 Zod Schema，再透過 Void 的 defineHandler 回傳 API 資料。

不過要先區分兩件事：

1. Request Validation：驗證前端傳來的資料，Void 有內建整合。
2. Response Validation：驗證後端準備回傳的資料，需要主動呼叫 Zod。

Void 官方目前的 withValidator() 主要處理 body、query、params，沒有提供對應的 response 驗證欄位。

## 已驗證(對照本機 void@1.2.1 原始型別)

`node_modules/void/dist/handler-*.d.mts` 裡的定義:

```ts
type ValidatorSlots = {
  body?: StandardSchemaV1;
  query?: StandardSchemaV1;
  params?: StandardSchemaV1;
};
```

- 沒有 `response` 欄位 → void 不做 response 的 runtime 驗證。
- `void/drizzle-zod` 只是 `export * from "drizzle-zod"`,跟直接裝 `drizzle-zod` 完全一樣。

## Request 側:可以直接用 Drizzle 衍生的 schema

Zod v4 原生實作 Standard Schema,`createInsertSchema(table)` 的結果可以直接丟進 `withValidator`,不用再包一層:

```ts
export const POST = defineHandler.withValidator({
  body: createInsertSchema(funds),
})((c, { body }) => { ... });
```

## Response 側:只有型別安全,沒有 runtime 驗證

[void.cloud/guide/type-safety](https://void.cloud/guide/type-safety) 講的是**編譯期型別推導**,不是 runtime 驗證:

| | 型別安全(void 有) | Runtime 驗證(void 沒有) |
|---|---|---|
| 什麼時候 | `tsc` 編譯時 | 每次實際回應時 |
| 檢查對象 | 程式碼宣稱的回傳型別 | 實際送出的 JSON |
| 執行後 | 型別消失 | 每次 `safeParse` |

TypeScript 只相信你寫的型別。DB 裡的實際資料(舊資料的 null、ingest 寫進的怪值)、`as` 轉型、`any`,都可能讓型別看起來對、實際 JSON 卻錯。要抓這類問題只能靠 runtime 驗證。

## 這個 repo 的實際狀況

`routes/_bridge.ts` 把所有請求整包轉給 Hono(`src/app.ts`),void 只負責建置、部署、D1 binding。所以:

| 層級 | void 原生寫法 | 本 repo |
|---|---|---|
| Request 驗證 | `withValidator()` | `@hono/zod-validator` + `src/validation.ts` 的 `validate()` |
| Response 驗證 | 沒有,要自己 `.parse()` | 自己寫的 `responds()` middleware + `strictObject` |
| 前端型別推導 | `void/client` | 用不到(void 只看到一個通用 handler) |

## 結論

- void 給你:request 的 runtime 驗證 + response 的編譯期型別。
- response 的 runtime 驗證不管用哪個框架都要自己寫。
- 這個 repo 兩層都手寫,是因為路由走 Hono 而不是 void 的逐路由 `defineHandler`。改成 void 原生能省掉的只有 request 外面那層 Hono 包裝。

## 參考文件

### Void 官方
- [Server Routing — Validation](https://void.cloud/guide/server-routing):`defineHandler.withValidator()` 只處理 `body`、`query`、`params` 三種輸入。
- [Type Safety](https://void.cloud/guide/type-safety):response 型別從 Drizzle 欄位推導,屬於編譯期檢查。
- [Database](https://void.cloud/guide/database):`void/drizzle-zod` 的 `createInsertSchema` / `createSelectSchema` 用法。
- [Typed Fetch](https://void.cloud/guide/typed-fetch):前端 `void/client` 的 `fetch` 怎麼拿到路由型別。
- 本機離線版:`node_modules/void/docs/guide/` 底下同名的 `.md` 檔。

### Drizzle / Zod
- [Drizzle ORM — Zod](https://orm.drizzle.team/docs/zod):`createSelectSchema` 如何從欄位型別與 nullable 產生 zod schema。
- [Zod — Objects](https://zod.dev/api?id=objects):`z.object()` 會默默移除多的欄位,`z.strictObject()` 則直接報錯。
