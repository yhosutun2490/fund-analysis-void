# Step 1：Drizzle Schema（SQLite 版）—— 資料合約的根

> 對應學習路線：[2.learning-roadmap.md](./2.learning-roadmap.md) → Step 1

本文說明 Drizzle ORM 如何以 TypeScript 宣告 SQLite Schema，以及這份宣告如何同時驅動
**查詢型別推導**（drizzle-orm）與 **migration 產生**（drizzle-kit）。

---

## 核心觀念：Schema 是唯一真相來源

```
src/db/schema.ts
      │
      ├─▶ drizzle-orm   讀取欄位物件 → 組 SQL 查詢字串、推導 TS 型別
      └─▶ drizzle-kit   讀取欄位物件 → 與 DB 比對 → 產生 migration SQL
```

**重要**：所有 table 都必須 `export`，否則 `drizzle-kit` 做 migration diff 時讀不到。

---

## 三種宣告語法

```ts
// ① 具名 import（最常見，本專案使用此方式）
import { sqliteTable, integer, text } from "drizzle-orm/sqlite-core";

export const users = sqliteTable("users", {
  id:    integer().primaryKey({ autoIncrement: true }),
  email: text().notNull().unique(),
});

// ② callback：欄位 builder 由參數 t 提供
export const users = sqliteTable("users", (t) => ({
  id: t.integer().primaryKey({ autoIncrement: true }),
}));

// ③ import * as t（適合在 sqliteTable 的 callback 內統一使用）
import * as t from "drizzle-orm/sqlite-core";
```

### 本專案用法（schema.ts 第 3 行）

```ts
import { index, integer, primaryKey, real, sqliteTable, text }
  from "drizzle-orm/sqlite-core";
```

使用具名 import ①，欄位名稱手動指定 snake_case 對應（如 `text("fund_id")`）。

---

## callback 裡兩個參數的區分

`sqliteTable` 可接受**三個參數**，第三個參數的 callback 才是 table 實體（欄位物件集合）：

```ts
sqliteTable(
  "users",
  { email: text().notNull() },          // ← 欄位定義（第二個參數）
  (table) => [                          // ← 第三個參數：table 是已建好的欄位物件
    uniqueIndex("email_idx").on(table.email),
  ]
);
```

### 本專案的 index 宣告

```ts
// src/db/schema.ts（funds 表）
export const funds = sqliteTable(
  "funds",
  { /* 欄位 */ },
  (t) => [                              // 這個 t 是欄位物件（不是 builder）
    index("idx_funds_group").on(t.fundGroup),
    index("idx_funds_category").on(t.category),
    index("idx_funds_rr").on(t.rr),
    index("idx_funds_area").on(t.investmentArea),
  ],
);

// fund_risk 表：複合主鍵 + 索引
export const fundRisk = sqliteTable(
  "fund_risk",
  { /* 欄位 */ },
  (t) => [
    primaryKey({ columns: [t.fundId, t.asOf] }),
    index("idx_risk_asof").on(t.asOf),
  ],
);
```

> **容易混淆點**：第二個參數 callback 的 `t` 是 column builder（`t.integer()`、`t.text()`）；
> 第三個參數 callback 的參數是**已建好的欄位物件**，用來引用欄位定義 index/constraint。

---

## 欄位命名：JS 鍵 vs SQL 欄位名

本專案採用**明確指定**方式：

```ts
fundId: text("fund_id").primaryKey(),   // JS 鍵 = fundId，SQL 欄位 = fund_id
asOf:   text("as_of").notNull(),
```

另一種做法是用 `snakeCase.table(...)` builder 自動把 `fundId` 轉換成 `fund_id`，省去到處寫別名。

---

## 欄位物件的本質：JS 物件，不是 JSON

`integer().notNull()` 是真實的函式呼叫，回傳的是一個**欄位 metadata 物件**：

```ts
{
  name: "id",
  columnType: "SQLiteInteger",
  notNull: true,
  primary: true,
  // ...
}
```

- **drizzle-orm**：讀取這些 metadata，在執行期組 SQL 字串（`select "fund_id" from funds`）
- **drizzle-kit**：import 你的 schema 檔，將物件**序列化成 JSON snapshot**，與資料庫比對差異，輸出 migration SQL

---

## TypeScript 型別層：泛型鏈推導

每個 builder 方法都帶泛型參數，每呼叫一個方法，型別就被改寫：

```ts
text()          // data: string | null,  notNull: false
  .notNull()    // data: string,          notNull: true
  .unique()     // + unique: true
  .default("x") // + hasDefault: true
```

```ts
// 進階：$type<>() 只影響 TS 型別層，不影響 DB 欄位
role: text().$type<"guest" | "admin">().default("guest"),

// enum: [] 是 runtime 層，drizzle-zod 產生 z.enum([...])
roleB: text({ enum: ["guest", "admin"] }),
```

## Migration 設定

```ts
// drizzle.config.ts
import { defineConfig } from "drizzle-kit";

export default defineConfig({
  dialect: "sqlite",
  schema:  "./src/db/schema.ts",
});
```

### Migration 產物結構

```
drizzle/
├ 0000_init.sql          ← 要執行的 SQL
└ meta/
   ├ 0000_snapshot.json  ← schema 序列化後的 JSON（diff 的依據）
   └ _journal.json       ← migration 的順序紀錄
```

`drizzle-kit generate` 比對的是這份 **JSON snapshot**，而不是直接掃資料庫。

## npm 模組解析：TS 型別 vs Runtime

```json
// drizzle-orm/package.json（exports map）
"./sqlite-core": {
  "import": {
    "types":   "./sqlite-core/index.d.ts",  // tsc 讀這個（型別定義）
    "default": "./sqlite-core/index.js"     // Node/Worker 執行這個（真實邏輯）
  }
}
```

## Runtime 驗證：drizzle-zod 整合

Drizzle 的型別推導是**編譯期**的，不保證 runtime 資料正確。
`drizzle-zod` 讓你直接從 table 定義衍生 Zod Schema：

```ts
import { createInsertSchema, createSelectSchema } from "drizzle-zod";
import { users } from "./schema";

// createInsertSchema → 輸入端（request body）常用
// createSelectSchema → 輸出端（response 契約保證）常用
```

### 為什麼需要 runtime 驗證？

| 情況 | TypeScript 能抓到？ | Zod 能抓到？ |
|------|:---:|:---:|
| 程式碼型別宣告錯 | ✅ | ✅ |
| `as` 轉型繞過型別 | ❌ | ✅ |
| 舊 DB 資料是 null（但型別說非 null）| ❌ | ✅ |
| ingest 寫進怪值 | ❌ | ✅ |

---

## CRUD Schema 衍生模式

同一張表通常只呼叫一次 `createInsertSchema`，再用 Zod 方法衍生出各種操作的 schema：

```ts
import { sqliteTable, integer, text } from "drizzle-orm/sqlite-core";
import { createInsertSchema, createSelectSchema } from "drizzle-zod";

export const users = sqliteTable("users", {
  id:   integer().primaryKey({ autoIncrement: true }),
  name: text().notNull(),
  age:  integer().notNull(),
});

// 基礎：可寫入欄位（排除 DB 自動產生的 id）
const writable = createInsertSchema(users, {
  name: (s) => s.min(1).max(50),
  age:  (s) => s.int().min(0).max(150),
}).omit({ id: true });

// 從 writable 衍生各種操作
export const createUserSchema  = writable;                       // POST：必填
export const updateUserSchema  = writable.partial();             // PATCH：全部選填
export const renameUserSchema  = writable.pick({ name: true });  // 只能改名
export const replaceUserSchema = writable.required();            // PUT：全部必填

// 至少提供一個欄位的 PATCH
export const updateUserNonEmpty = updateUserSchema.refine(
  (d) => Object.keys(d).length > 0,
  { message: "至少要提供一個欄位" },
);

// 輸出端用 selectSchema（型別包含 id 與所有欄位）
export const userResponseSchema = createSelectSchema(users);
```

### 為什麼 insert/select 要分開？

`createInsertSchema` 反映**可寫入**的欄位（`id` 有 default，常 omit 掉）。
`createSelectSchema` 反映**從 DB 讀出**的完整資料（含 `id`、DB 計算欄位）。
兩者 nullable 規則不同，共用一個會產生型別漂移。

## 對應本專案的 schema.ts

| Table | 說明 | 主鍵型式 |
|---|---|---|
| `funds` | 基金基本資料，每檔一列 | `fund_id` text PK |
| `fundRisk` | 風險指標月度快照 | `(fund_id, as_of)` 複合 PK |
| `fundSeries` | 含息累積報酬序列 JSON | `fund_id` text PK |
| `ingestRuns` | 爬取執行紀錄 | `id` autoIncrement integer PK |

所有 table 均已 `export`，drizzle-kit 可做 migration diff。
`text("fund_id")` 的字串參數對應 SQL 欄位名，JS 屬性名用 camelCase（如 `fundId`）。
